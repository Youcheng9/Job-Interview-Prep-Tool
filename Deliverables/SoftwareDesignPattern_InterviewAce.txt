--- InterviewAce Software Design Pattern ---

Selected Design Pattern: Service Layer Pattern

Recommendation
InterviewAce should use the Service Layer pattern for the backend architecture.

The current backend design places too much responsibility inside the API routers. For example, the scoring router handles request validation, answer creation, score calculation, score persistence, AI feedback workflow, and background task coordination. That means the router is acting as both a controller and a business logic service.

The Service Layer pattern fixes this by separating request handling from application logic.

Pattern Purpose
The Service Layer pattern organizes business operations into service classes or modules. Routers/controllers only handle HTTP requests and responses, while services coordinate workflows such as authentication, question retrieval, scoring, feedback generation, and history assembly.

  routers/

  feedback_agent.py

Layer Responsibilities

1. Routers / Controllers
- Receive HTTP requests
- Validate request schemas
- Call the correct service method
- Return API responses
- Avoid direct business logic and complex database workflows

2. Services
- Contain application workflows
- Coordinate repositories, ML helpers, and feedback generation
- Enforce business rules
- Keep use cases organized and testable

Example services:
- AuthService
- QuestionService
- ScoringService
- HistoryService

3. Repositories
- Encapsulate SQLAlchemy database queries
- Create, update, retrieve, and delete database records
- Keep database logic out of routers and services

Example repositories:
- UserRepository
- QuestionRepository
- AnswerRepository
- ScoreRepository

4. Domain / ML Helpers
- Handle scoring algorithms, embeddings, cosine similarity, STAR evaluation, and AI feedback generation
- Stay independent from HTTP request handling

Why This Pattern Fits InterviewAce

The Service Layer pattern fits InterviewAce because the project includes multiple workflows that combine API handling, database persistence, AI/ML scoring, and feedback generation. These workflows are more complex than basic CRUD operations.

InterviewAce includes:
- User registration and JWT authentication
- Password reset through Brevo SMTP email
- Role and level based question delivery
- Text and speech answer submission
- AI-powered scoring using sentence-transformers
- Deterministic rubric-based feedback
- AI Coach chat through Ollama
- Answer history and progress tracking
- PostgreSQL persistence
- Docker-based deployment

Without a service layer, routers will continue to grow and become harder to test, debug, and maintain. With a service layer, each backend module has one clear responsibility.

Before Service Layer

scoring.py router:
- Parses request
- Creates Answer record
- Calls ML scorer
- Creates Score record
- Generates feedback
- Handles AI feedback state
- Starts background task
- Returns response

After Service Layer

scoring.py router:
- Receives request
- Calls ScoringService.submit_answer(...)
- Returns response

ScoringService:
- Creates Answer record through AnswerRepository
- Calls scorer.py for multi-dimensional scoring
- Calls feedback_agent.py for feedback
- Stores Score through ScoreRepository
- Coordinates AI Coach feedback workflow

Benefits

1. Cleaner Routers
Routers become easier to read because they only manage HTTP request and response behavior.

2. Better Maintainability
Business logic is grouped into services, so future changes to scoring, feedback, or history do not require editing large router files.

3. Easier Testing
Services can be unit tested without starting the FastAPI server.

4. Reusable Logic
The same service methods can be reused by different endpoints or background jobs.

5. Clearer Architecture
The backend matches the architecture diagram: Presentation Layer calls Application/API Layer, which delegates to Service Layer, Data Layer, and AI/ML helpers.

Final Design Pattern Statement

InterviewAce uses the Service Layer design pattern to separate API routing from business logic. FastAPI routers act as controllers that receive requests and return responses. Service modules such as AuthService, QuestionService, ScoringService, and HistoryService coordinate core workflows, including authentication, question delivery, AI scoring, deterministic feedback, AI Coach chat, and progress history. Repository modules isolate SQLAlchemy database operations, while ML helpers handle embedding, cosine similarity scoring, and feedback generation. This pattern improves maintainability, testability, and separation of concerns as InterviewAce grows.
